# Git 分支（Branch）入门

> 本文是给零基础学习者的 Git 分支介绍资料。

## 什么是分支

分支（branch）是 Git 里最强大的功能之一。**简单说，分支就是一条独立的开发线**——就像在一本书里夹书签，你可以在某个位置开始写一个不同的版本，而不会影响原来的内容。

**类比**：想象你在写一本小说。主线是"正传"，你想试试写个"番外篇"——如果番外写得不好，撕掉重来也不影响正传。分支就是这个"番外篇"的草稿纸。

## 为什么需要分支

- 团队协作：每个人在各自的分支上干活，互不干扰
- 实验新功能：失败了大不了删掉分支，主线安全
- 修复 Bug：从主分支拉一个分支专门修，修完再合并回去

## 核心命令

| 命令 | 作用 | 大白话 |
|------|------|--------|
| `git branch` | 查看所有分支 | 看看现在有哪些草稿纸 |
| `git branch 名字` | 创建新分支 | 拿一张新草稿纸 |
| `git checkout 名字` | 切换到某分支 | 拿起那张草稿纸来写 |
| `git checkout -b 名字` | 创建并切换 | 拿新纸并且马上开写 |
| `git merge 名字` | 合并分支 | 把番外篇的内容抄回正传 |
| `git branch -d 名字` | 删除分支 | 扔掉不需要的草稿纸 |

## 一个完整流程示例

```bash
# 1. 查看当前分支（默认在 main 或 master）
git branch

# 2. 创建一个新分支做实验
git branch experiment

# 3. 切换到新分支
git checkout experiment

# 4. 在新分支上随便改、随便提交
git add .
git commit -m "实验性改动"

# 5. 切回主分支，看看主分支没受影响
git checkout main
git log --oneline   # 主分支上还是原来的提交

# 6. 觉得实验不错，合并回主分支
git merge experiment

# 7. 用完的分支可以删掉
git branch -d experiment
```

## 常见坑

1. **忘记切换就提交**：提交到了错误的分支。解决：先 `git branch` 确认自己在哪。
2. **合并冲突**：两个分支改了同一处。解决：冲突标记 `<<<<<<<` 让你手动选，选完再 `git add` + `git commit`。
3. **误删分支丢工作**：删除前确认改动已合并或已提交，`-D` 强制删除要三思。

## 小结

分支 = 独立的开发线 = 可以安全实验的草稿纸。记住：**分支让你大胆试错，主线永远安全。**
