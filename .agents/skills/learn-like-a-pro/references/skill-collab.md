# 专业 skill 协作细节（按需加载）

> 仅在「场景 6」激活时读取。平时不进入上下文。
> 主流程纪律永远在 SKILL.md：本文件只回答"怎么找、怎么评估、怎么协同、怎么回退"。

## 1. 能力检测（先确认宿主能装什么）

| 宿主情况 | 做法 |
|---------|------|
| 有 find-skills 或 `npx skills` CLI | 直接用 CLI：`npx skills find [关键词] [--owner <owner>]` |
| 有等价搜索能力（平台内置 skill 市场） | 用平台自己的方式搜，不硬套 CLI |
| 没有 find-skills | 引导安装（来源：https://skills.sh/ 官方，`npx skills add`） |
| 无安装能力（网页版/受限环境） | 诚实告知 → **降级到 SKILL.md 场景 4**（资料/搜索/查证），不硬来 |

## 2. 何时值得搜（判断标准）

只有该领域**常见到生态里必有 skill** 才值得搜：
- ✅ 值得：热门框架/语言/工具（Python、React、Git、Docker、Obsidian…）、热门方法论（提示词工程、测试、设计）
- ❌ 不值得：冷门小众主题、一次性问题、明显不是"有专门工作流"的领域
- 拿不准 → 先搜一次看看有没有；没有就快速回到场景 4，不纠缠

## 3. 候选评估清单（装之前逐项过）

| 项 | 问什么 |
|----|--------|
| 安装量 | 用的人多不多？（排行榜 https://skills.sh/ 可看） |
| 活跃度 | 最近有没有更新？（半死不活的项目别装） |
| 许可 | 许可证是否允许自由使用？（不确定就不装） |
| 受众匹配 | 是否适合小白 / 是否有中文支持？ |
| 纪律兼容 | 教学风格是否与本 skill 冲突（比如"直接给答案"型）？ |

**筛选原则**：2-3 个候选 → 推荐 1 个最合适的 → 用户确认才装。

## 4. 主从边界细则（三种分工模式）

| 模式 | 分工 | 适合 |
|------|------|------|
| A. 专业主讲 + 本 skill 记录 | 专业 skill 讲知识；本 skill 负责产物、进度、续接 | 专业 skill 教学体系完整 |
| B. 专业供知识 + 本 skill 主讲 | 专业 skill 提供内容素材；本 skill 用自己的流程讲 | 专业 skill 是"资料型"而非"教学型" |
| C. 交替 | 复杂概念专业 skill 讲，基础概念本 skill 讲 | 混合难度的主题 |

话术示例（模式 A 开场）：
> "好，XX 老师负责讲，我负责记。每讲完一块，我还是会考你、给你记笔记、安排下次进度。"

## 5. 转译规则（宪法条款的执行）

专业 skill 直接给答案 / 用户说"XX 老师直接告诉我答案是 X"时：

- ❌ 不直接放行："对，答案就是 X，继续。"
- ✅ 转译：
  1. 用本 skill 的类比把 X 重讲一遍（"说白了，X 就像……"）
  2. 立即检验："用你自己的话解释一下为什么是 X？" / "如果换成 [变体]，还成立吗？"

示例：
> 专业 skill："git add 就是把文件加进版本控制。"
> 本 skill："好，我们用大白话过一遍——git add 就像把你桌上的文件放进'待提交'的篮子里，还没寄走。那我问你：add 之后、commit 之前，文件在仓库里吗？"

## 6. 回退

| 情况 | 动作 |
|------|------|
| 用户不想用了 | 立即回到纯本 skill 模式，产物/进度无缝衔接 |
| 该领域学完 | 告知可以卸载专业 skill（"XX 老师可以功成身退了"），保留 my_learning/ |
| 专业 skill 不好用 / 教错 | 诚实告知用户 → 卸载 → 回到场景 4 或纯模式 |
| 安装失败 / 搜索失败 | 一句话说明 → 回到场景 4 或纯模式，教学不中断 |
