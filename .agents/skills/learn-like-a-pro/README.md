# learn-like-a-pro — 小白专属 AI 学习教练

> 一个专为零基础用户设计的 AI 学习助手 Skill。采用苏格拉底教学法、费曼学习法和支架理论（Scaffolding），通过互动式对话引导你从零到掌握，并自动生成可复用的学习日志。
>
> **一句话定位：它是你的"学习教练 + 学习记录仪"——负责把你教会，并把你学过的、踩过的坑，都变成能回看的资料。**

## 1. 这个 Skill 能为你做什么？

### 三个承诺

| 承诺 | 具体表现 |
|------|---------|
| **任何领域都能学** | AI Agent、Python、Git、Markdown……任何技术主题都适用。每个主题独立存档，可以同时学多个领域，互不干扰 |
| **当你的好老师** | 先诊断你的基础再开讲；教学顺序科学（动机 → 类比 → 直觉 → 定义）；绝不说"你错了"；每单元拆小、强制动手、主动回忆测试 |
| **输出学习日志** | 每次学习自动沉淀 6 种产物（笔记/速查卡/自测题/下一步/术语表/进度），纯 Markdown，可复习、可迁移、可交给任何 AI 接着教 |

### 三个要知道的事实（避免误会）

1. **目前偏向技术学习**：六步法（诊断→拆解→教学→实践→测试→产物）最适合编程、工具、框架类内容。学语言、学历史也能用，但"动手实践"和"产物"的设计是围绕技术场景写的。
2. **它不会替你学**：它强制你动手、复述、测试——这正是它好的地方。如果你只想"听"不想"做"，它会卡住你（主动回忆没过关就标记 `needs_review`，不让你推进）。
3. **日志按"单元"记，不是按"句话"记**：一个单元完整学完才写入产物。学一半中断（比如"我累了今天先到这"），它只保存进度和已讲部分，**不会假装把没讲的内容补完整**——下次续接时从剩下一半接着教，教完、测过，才补全产物。宁可欠着，也不让你糊弄过去。

## 2. 怎么用它（最重要的使用规则）

### 2.1 安装后你拿到的是什么

安装本 Skill 时，你拿到的是一个**独立的 Skill 文件夹**：

```
learn-like-a-pro/
├── SKILL.md                          ← 【核心】教学指令（AI 靠它知道怎么教你）
├── README.md                         ← 本文件（面向使用者）
├── evals/
│   ├── evals.json                    ← 13 个测试场景（验证 Skill 质量）
│   └── files/ai-agent/               ← 测试用的模拟学习存档
└── references/
    ├── resume.md                     ← 【核心】续接教学精简指令（保留教学规则、省 Token）
    └── templates/                    ← 6 个产物模板
```

**`my_learning/`（你的学习产物目录）不包含在安装包里**——它会在你**第一次使用 Skill 学习时自动生成**。也就是说：

- 刚安装 = 只有 Skill（老师），还没有成绩单
- 第一次学习后 = 项目里出现 `my_learning/<主题>/`，成绩单开始积累

### 2.2 一句话版（记不住细节？记住这张）

| 你想干嘛 | 打开/拷贝什么 |
|---------|--------------|
| 用这个 Skill 学新东西 | 打开**项目根目录**作为工作区（不是 Skill 文件夹！） |
| 换一个 AI 只看学习成果 | 只拷贝 `my_learning/<主题>/` 过去就行 |
| 换一个 AI 继续学某个主题 | 拷贝 **Skill 文件夹 + `my_learning/<主题>/`**，并保持相对结构 |

### 2.3 场景一：用这个 Skill 学习 → 打开项目根目录

假设你把 Skill 装到了某个项目里，结构是这样的：

```
你的项目根目录/                      ← 打开这个作为工作区 ✅
├── .agents/skills/learn-like-a-pro/   ← 老师（Skill 本体）
├── my_learning/                       ← 你的成绩单（学习存档，首次学习后生成）
└── （其他项目文件）
```

**为什么不能只打开 Skill 文件夹？**

AI 找学习存档的路径是 `my_learning/<主题>/state.json`——这个路径是**相对于项目根**写的。如果只把 Skill 文件夹作为工作区：

- ✅ AI 能看到 Skill（能教）
- ❌ AI 看不到 `my_learning/`（它在 Skill 文件夹**外面**）
- 结果：每次新对话都找不到存档 → **续接失效，被迫重新诊断**

> **规则：工作区 = 项目根（Skill 和 my_learning 的共同父目录）。** 这样 AI 既找到老师，又找到你的成绩单。

### 2.4 场景二：换 AI 只看学习成果 → 只拷贝主题文件夹

```
拷贝：my_learning/python/        ← 够了 ✅
```

因为 `notes.md`、`cheatsheet.md`、`glossary.md` 都是**纯 Markdown**，任何 AI 打开就能读懂。**不需要 Skill**——你只是想复习，不是想继续学。

### 2.5 场景三：换 AI 继续学某个主题 → 两个一起拷贝

```
新项目/
├── .agents/skills/learn-like-a-pro/   ← 老师（Skill）必带
└── my_learning/python/                ← 成绩单（存档）必带
```

**只拷贝主题文件夹不够**，因为：
1. 没有 Skill，新 AI 不知道该用哪种方式教你（不知道诊断 5 问、苏格拉底检验、产物生成这些规则）
2. 即使有 Skill，如果目录结构不对（主题文件夹没放在 `my_learning/` 下），Skill 按 `my_learning/<主题>/state.json` 的路径找不到存档，照样重新开始

> **规则：换 AI 续学 = "老师"和"成绩单"必须保持原相对位置一起搬。**

### 2.6 完整目录总览（首次学习后的样子）

```
learn-like-a-pro/
├── SKILL.md                          ← 【核心】教学指令
├── README.md                         ← 本文件（面向使用者）
├── evals/
│   ├── evals.json                    ← 13 个测试场景
│   └── files/ai-agent/               ← 测试用的模拟学习存档
└── references/
    ├── resume.md                     ← 续接教学精简指令
    └── templates/                    ← 6 个产物模板

my_learning/                          ← 运行时自动生成（首次学习后出现）
├── <主题1>/                          ← 目录名英文 kebab-case，如 ai-agent/
│   ├── state.json                    ← 进度存档（机器读，你不用打开）
│   ├── notes.md                      ← 学习笔记（追加）
│   ├── cheatsheet.md                 ← 速查卡（追加）
│   ├── quiz.md                       ← 自测题（追加）
│   ├── next-steps.md                 ← 下一步指引（覆盖）
│   └── glossary.md                   ← 术语表（追加）
└── <主题2>/                          ← 如 python/
```

## 3. 学习产物说明

一个主题学完后，`my_learning/<主题>/` 下会出现 6 个文件，分三类：

| 类别 | 文件 | 一句话 | 什么时候看 |
|------|------|--------|-----------|
| **① 学习内容** | `notes.md` | 详细笔记（大白话+类比+定义+坑） | 复习、回看 |
| | `cheatsheet.md` | 一页速查卡（表格） | 快速回忆、考前扫一眼 |
| | `glossary.md` | 术语表（每个术语配"人话版"） | 遇到不懂的词 |
| **② 自测** | `quiz.md` | 自测题（带折叠答案） | 检验自己真懂假懂 |
| **③ 进度/计划** | `next-steps.md` | 已掌握+待学+练习建议 | 知道下一步干嘛 |
| | `state.json` | 机器读的进度存档（学到哪、哪些卡住） | 只有 AI 读，你不用打开 |

**记忆法**：前 5 个是给你看的文档（学习日志），最后 1 个 `state.json` 是给 AI 看的"进度存档"。

### 各产物细节

- **notes.md**：按单元组织，每单元含大白话解释、生活类比、正式定义、易踩坑 → **追加**，历史保留
- **cheatsheet.md**：核心概念表 + 常用命令 + 一个"记住这个类比" → **追加**
- **quiz.md**：每单元 3-5 题，`<details>` 折叠答案，防止偷看 → **追加**
- **next-steps.md**：已掌握/待学习/练习建议/推荐资源 → **覆盖**（状态变化必须最新）
- **glossary.md**：术语/大白话/类比/首次出现日期 → **追加**
- **state.json**：当前进度、单元状态、诊断结果、会话历史 → **覆盖**（实时）

## 4. 核心设计

### 4.1 轻量化续接（省 Token，不降质量）

- **首次学习**：加载完整 `SKILL.md`（~680 行）→ 诊断 → 建状态文件
- **续接学习**：只加载 `references/resume.md`（~200 行）+ `state.json`（~30 行）
  - `resume.md` 保留核心教学规则（费曼导入、苏格拉底检验、支架练习、产物生成）
  - `state.json` 提供实时进度
- 续接 Token 消耗约为完整版的 **1/3**，教学质量不降低

**上下文吃紧怎么办**：如果对话变长、感觉 AI"记性变差"（小上下文模型尤其明显），最有效的动作是**结束当前对话，用"继续学 XXX"续接**——续接会自动走 `resume.md`（Token 省 63%），而不是去删减 `SKILL.md`。`SKILL.md` 是教学纪律的完整版（类比先行、苏格拉底检验、支架练习全靠它），删它等于把保证质量的规则删掉——省了 token 丢了质量，得不偿失。

### 4.2 产物按"单元"更新，不按"句话"更新

不是每轮对话都写日志，而是**每个学习单元完成后**更新一次。追加策略见上表——历史记录永远保留，只有 `next-steps.md` 和 `state.json` 覆盖（状态必须最新）。

### 4.3 多轮对话怎么续上的（state.json 示例）

```json
{
  "topic": "AI Agent",
  "topic_slug": "ai-agent",
  "current_unit_index": 2,
  "units": [
    {"name": "AI Agent 是什么", "status": "completed", "mastered": true},
    {"name": "Agent 是怎么思考的", "status": "needs_review", "mastered": false},
    {"name": "Skill 是什么", "status": "in_progress", "mastered": false}
  ],
  "diagnosis": {"current_knowledge": "完全零基础", "goal": "做一个简单 Agent"}
}
```

**`needs_review` 是什么意思**：当某单元卡住超过 3 次或测试 0-1 题对时，标记为"需重学"，**进度不推进**——续接时 AI 会优先带你重学这个单元，而不是跳过它。这保证"学完"和"掌握"是两回事：流程走完 ≠ 真懂了。

**续接流程**：
1. 用户说"继续学 AI Agent"
2. AI 加载 `resume.md` + `state.json`
3. 发现 `needs_review` 单元 → 优先重学；否则从 `current_unit_index` 继续
4. 确认"上次学到 X，今天继续吗？" → 用户确认 → 直接接着教，**不再重新问诊断 5 问**

### 4.4 多个主题并行学，互不干扰

- 每个主题独立目录：`my_learning/ai-agent/`、`my_learning/python/`
- 目录名统一**英文 kebab-case**（`ai-agent`、`git-basics`），中文名存在 `state.json` 的 `topic` 字段
- 切换主题 = 读对应目录的存档，无缝切换

### 4.5 环境没有文件权限时怎么办（fallback）

如果 AI 运行在无法写文件的对话环境（如网页版），产物不会丢——AI 会把产物完整内容输出在对话里，并告诉你手动保存到 `my_learning/<主题>/`。**产物生成是核心承诺，任何环境都不跳过。**

### 4.6 实践型主题适配（做游戏 / 写网站 / 写脚本）

学"做一个能跑的东西"（比如一款贪吃蛇小游戏）时，诊断会自动加深：在基础 5 问之后追加 4 问——**上手程度**（写过代码吗）、**设备与环境**（装了什么工具）、**产物想象**（做出来长什么样、在哪玩）、**类型偏好**（想做什么，给你 2-3 个选项）。

- 每条追问都在为"怎么拆地图、用什么工具、产物长什么样"提供依据，不是拖延
- 关键的一问是**工具选型**：小白什么也没装 → 优先零安装方案（如网页版 p5.js），而不是上来让 TA 装 VS Code + Python 配环境——选错工具是项目型学习劝退的第一大原因
- 学习地图会把**环境搭建**作为第 1 个单元（地基），地图终点是"做出一个能玩的产物"
- 每单元按「讲 → 验 → 练 → 测」四拍走完，每拍至少 1 次提问互动

## 5. 工作原理（六步循环）

```
[激活]
  ↓
[检测 my_learning/<主题>/state.json]
  ├─ 存在 → 加载 resume.md + state.json → 确认续接 → 直接跳到第 ③ 步
  └─ 不存在 → 走完整流程
    ↓
① 诊断起点（基础 5 问；实践型主题追加 6-9 问）→ 创建 state.json
  ↓
② 构建学习地图（拆成 5-10 个最小可学单元）
  ↓
③ 知识构建（Motivation → Analogy → Intuition → Definition）
  ↓
④ 动手实践（光听不练 = 白学）
  ↓
⑤ 主动回忆测试（3 题，检测真懂还是假懂）
  ↓
⑥ 产物生成（追加更新）+ 更新 state.json
  ↓
[循环到下一个单元，或收尾]
```

## 6. 对话质量验证（测评结果）

> 本 Skill 用 **skill-creator 方法论** 做了完整的量化测评：让"装了本 Skill 的 AI"和"没装的普通 AI"分别回答真实学习场景，由独立评分代理按客观断言打分，对比差距。测评经过两轮迭代（详见下方"准确度评估"）。

### 测评结果（13 个场景，68 条断言）

| 指标 | 装 Skill 的 AI | 普通 AI（无 Skill） | 差距 |
|------|---------------|-------------------|------|
| 综合通过率（12 个经典场景） | **100%** | **74.4%** | **+25.6%** |
| 实践型主题诊断（eval 13 新增） | **8/8** | **6/8** | 普通 AI 让小白直接装 VS Code，无零安装方案 |

### 十二个场景覆盖了什么

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 零基础学 AI Agent | 诊断纪律：只问第 1 问、不直接讲概念、语气鼓励 |
| 2 | 动手写第一个 Skill | 教学前诊断、给出具体格式指令、引导而非代做 |
| 3 | 迷茫不知道学什么 | 情绪支持、兴趣发现、不过早推荐 |
| 4 | 续接学习（"继续学 AI Agent"） | 检测存档、跳过重复诊断、`needs_review` 优先重学 |
| 5 | 无文件系统环境 | 承诺 fallback、告知保存路径、教学不中断 |
| 6 | 多轮完整教学对话（Markdown） | 完整教学链：诊断→地图→类比先行→苏格拉底检验→主动回忆 |
| 7 | 多轮对话·换技术主题（Python） | 验证教学纪律与主题无关（第二轮新增） |
| 8 | 多轮对话·非技术主题（历史） | 验证非技术主题适配，实践因地制宜（第二轮新增） |
| 9 | 内容正确性（Git commit） | 验证 AI 教的概念与官方语义一致（第二轮新增） |
| 10 | **长对话·15 轮耐力测试（Python）** | **验证规则是否随对话变长而漂移（第三轮新增）** |
| 11 | **资料驱动学习（用户发 Git 资料）** | **读取资料→基于资料教学→指出资料缺口（第四轮新增）** |
| 12 | **资料读不了的环境** | **诚实告知、粘贴 fallback、不编造（第四轮新增）** |
| 13 | **实践型主题诊断（做贪吃蛇游戏）** | **追加 6-9 问（经验/环境/产物想象/类型）、零安装方案选型、环境搭建为第 1 单元（第五轮新增）** |

### 关键发现（差距在哪里）

- **最核心的差距——"类比先于定义"**：完整教学对话中，普通 AI 教"轻量级标记语言"时是**定义先行、例子殿后**；装了本 Skill 的 AI 会先给"菜单上画记号"的生活类比，再给正式定义。这正是本 Skill 的教学铁律（ADR-101）。
- **诊断纪律**：普通 AI 会零诊断直接倒知识给小白；本 Skill 强制先问诊断 5 问，绝不跳过。
- **绝不信"懂了"**：用户说"感觉掌握了"时，普通 AI 直接继续；本 Skill 会用苏格拉底检验问题确认真懂。
- **长对话规则漂移**（第三轮新发现）：对话越长，普通 AI 越容易"忘规矩"——15 轮后半段它直接放行"感觉掌握了"、不再类比先行；装本 Skill 的 AI 到第 14 轮仍守纪律（详见下方"长对话测试"）。

### 测评怎么做的（简版）

1. 每个场景跑 2 个 AI：一个装本 Skill，一个不装（对照组）
2. 由独立评分代理按**可客观验证的断言**打分（如"第一轮只问诊断第 1 问""未出现'你错了'"）
3. 聚合所有场景的通过率，对比差距

> 测评数据与完整报告在安装包内 `learn-like-a-pro-workspace/` 目录（如有附带）。

### 准确度评估（13 个场景，68 条断言）

> 为了让使用者自己判断这个 Skill 的可靠程度，我们做了第二轮扩展测评：把多轮对话场景**换了不同主题**测试，并新增**内容正确性**验证。以下是完整结论，含局限。

#### 完整基准（13 个场景）

| 指标 | 装 Skill 的 AI | 普通 AI（无 Skill） | 差距 |
|------|---------------|-------------------|------|
| 综合通过率 | **100%** | **74.4%**（12 个经典场景）；eval 13 为 **6/8** | 新增场景拉开 +0.25 |

#### 换主题测试（教学纪律是否与主题无关）

| 多轮场景 | 装 Skill | 普通 AI | 结论 |
|---------|---------|---------|------|
| 学 Markdown（技术） | 6/6 | 5/6 | skill 保持满分 |
| 学 Python（技术） | 6/6 | 4/6 | skill 保持满分，普通 AI 反而更低 |
| 学中国近代史（非技术） | 7/7 | 6/7 | **非技术主题也能 100%** |

**结论**：教学纪律（先诊断 → 拆单元 → 类比先行 → 检验真懂）与主题无关。换技术主题 skill 表现不变；连非技术主题（历史）也全过——因为它自动把"动手实践"改成了"复述/画时间线/讲给别人听"，而不是生硬套用"打开终端写代码"（此规则现已写入 SKILL.md 明文）。

#### 内容正确性测试（教得对不对）

第一轮测试用的是"有无明显错误"的宽松检查，双方都通过（4/4），区分度不足。**第二轮改用正向检查**（要求主动讲对关键要素），结果：

| 场景（教 Git commit） | 装 Skill | 普通 AI | 差距在哪 |
|------|---------|---------|---------|
| 第一轮（宽松：无明显错误即过） | 4/4 | 4/4 | 双方内容都正确 |
| **第二轮（正向：必须主动讲对）** | **6/6** | **4/6** | 普通 AI 缺"本地/远程区分"和"查证引导" |

**正向检查的具体差距**：
- **主动区分本地与远程**：普通 AI 全程没提"commit 保存到本地仓库、不是上传 GitHub"；装 Skill 的 AI 明确讲了（这正是 skill 里"不把 commit 说成上传"的教学要求）。
- **引导查证**：装 Skill 的 AI 会引导"把终端输出发给我一起看""我们对照文档"；普通 AI 只是布置任务。
- **知识点本身双方都对**（commit 是本地快照、add 是暂存、先 add 后 commit）——知识正确性仍主要取决于模型。

**重要结论（诚实的边界）**：本 Skill 验证的是**"教得规范"**（诊断了吗？类比先行了吗？批评了吗？检验了吗？该讲的关键要素讲全了吗？），**不验证"知识对不对"**。如果某次教学讲错了概念，那通常是模型知识问题——但本 Skill 在"超纲场景"里有一条**不编造原则**：当主题超出 AI 的知识范围时，它不会编造，而是引导你一起搜索、阅读资料、对照文档验证（SKILL.md 场景 4）。

#### 长对话测试（15 轮耐力测试）

> 核心问题："长篇幅多对话下，还能保持回答质量与准度吗？"——即规则会不会随对话变长而漂移。

**测试设计**：15 轮连续对话，学 Python，覆盖完整流程：诊断 → 单元 1（print/变量）完整教学+检验 → 单元 2（if/else）→ **中途说"累了今天先到这"** → 下次"我回来了继续学" → 继续单元 2 → 收尾。8 条断言专门检查**后半段（第 12-14 轮）是否仍守纪律**。

| 指标 | 装 Skill | 普通 AI | 差距 |
|------|---------|---------|------|
| 15 轮长对话 | **8/8 (100%)** | **5/8 (62.5%)** | **+37.5%** |

**普通 AI 的规则漂移（实测证据）**：
- **第 13 轮**：用户说"我好像懂了"→ 普通 AI 直接说"完全正确！进入 elif"——**放行了**（前半段它还会检验）
- **第 14 轮**：用户说"感觉掌握了"→ 直接"第 5 课算过关了"——**又放行了**
- **后半段教 else/elif**：直接给代码和定义，**不再类比先行**（"就像/说白了"全文零出现）
- **全程无产物机制**：不提"笔记已保存"（普通 AI 没有产物系统）

**装 Skill 的 AI（实测证据）**：
- **第 12 轮教 else**：仍先给"天气预案：下雨带伞、否则戴帽子"类比，再给定义
- **第 13 轮**：用户说"好像懂了"→ 仍要求"用大白话讲一遍"+两个细节追问
- **第 14 轮**：仍做 3 问主动回忆测试，答完才推进
- **第 9 轮中断**：明确"进度写进 state.json，下次从 if 练习继续"；**第 10-11 轮续接**：不重新诊断、准确恢复位置

**结论**：**长对话确实会让普通 AI 的教学纪律漂移**（这正是你担心的"越聊越散"）；本 Skill 的价值在长对话中**不减反增**——因为它把规则写死在指令里，模型每轮都"看着规则"回复，到第 14 轮仍然守纪律。**对话越长，Skill 的稳定性优势越明显。**

**已知边界**：15 轮是当前测试上限；更长（50+ 轮）或多主题并行长对话尚未测试。

#### 资料驱动学习测试（用户发来资料/网址）

> 核心问题："用户找到学习资料发给我，这个工作流能很好地进行下去吗？"——包括能读资料和读不了两种情况。

| 场景 | 装 Skill | 普通 AI | 差距在哪 |
|------|---------|---------|---------|
| 能读资料（用户发 Git 分支文档） | **5/5** | **3/5** | 普通 AI 不指出资料缺口、有资料仍跳过诊断 |
| 读不了（无抓取/读文件工具） | 4/4 | 4/4 | 双方都诚实、都提供粘贴 fallback、都不编造 |

**诚实边界（重要）**：**"能不能读到"取决于 agent 模型能力，不是本 Skill 能给的**——测试证实普通 AI 也会诚实告知"读不了"、也会读文件。本 Skill 的真正价值在**读到之后**：
- **查漏补缺**：普通 AI"资料说什么就教什么"（照单全收，不指出资料缺远程分支）；装 Skill 的 AI 会主动标注资料缺口并纳入学习地图
- **教学纪律不因有资料而打折**：普通 AI 有资料后跳过诊断直接开讲；装 Skill 的 AI 仍先诊断（"我不会上来就开讲"）

**据此改进**：SKILL.md 与 resume.md 已新增"**资料驱动学习**"工作流（能力检测 → 读取 → 提炼 → 教学 → 查漏；读不了时诚实告知 + 粘贴 fallback + 不编造）。此规则已写入明文，不再依赖模型的自觉。

**一句话**：资料驱动的"上限"（读不读得到）取决于你用的 AI 模型；本 Skill 保证"下限"（读到之后查漏补缺、读不到不编造、教学纪律不丢）。

#### 使用者该怎么看这些数字（诚实解读）

1. **+25.6% 是"教学纪律"的提升，不是"知识水平"的提升**——它保证 AI 每次都按科学方法教你（先诊断、先类比、不批评、检验真懂、讲全关键要素），而不是偶尔做得好。对学习者来说，**一致性比峰值更重要**。
2. **普通 AI 本身也有 74%**——现代 AI 自带不错的教学能力。本 Skill 的价值是把"好的教学"从"偶尔发生"变成"每次发生"。
3. **100% 有"同源"水分**——测试断言是按本 Skill 的设计写的，天然偏向装了 Skill 的 AI。真实教学效果还需你亲自体验判断。
4. **未验证的盲区**：① 技能型非技术主题（弹钢琴、游泳这类"练"多于"学"的内容）；② 冷门领域的知识正确性（取决于模型知识，Skill 只能引导查证、不能保证正确）；③ 长期多单元教学（当前只测到单单元完整链路）。

#### 结论

本 Skill 是一套**经过量化验证的教学行为规范**：它能可靠地让 AI 按科学教学法陪你学习、把关键教学要素讲全、并在超纲时引导查证而非编造、同时自动沉淀学习日志；它**不承诺**提升 AI 的知识正确性。**用一句话说：它保证"教得对路、讲得齐全、不懂会查"，不保证"教得都对"——最后一点取决于你使用的 AI 模型本身，遇到可疑知识点请按它的引导一起查证。**

## 7. 安装

### 方法 1：直接放入项目

```bash
# 将本目录复制到你的项目 .agents/skills/ 下
cp -r learn-like-a-pro /your-project/.agents/skills/
```

### 方法 2：使用 skills CLI

```bash
npx skills add /path/to/learn-like-a-pro -y
```

> 装好后，如果你之前学习过（已有 `my_learning/`），记得把它一起迁移到新项目——否则新环境会重新开始。
