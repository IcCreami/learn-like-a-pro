# learn-like-a-pro — 你的 AI 学习管家

> 一个专为零基础用户设计的 AI 学习管家 Skill。采用苏格拉底教学法、费曼学习法和支架理论（Scaffolding），通过互动式对话引导你从零到掌握，并自动生成可复用的学习成果。
>
> **一句话定位（v1.5）：它是你的"学习管家 + 基础课老师"——负责把学习过程管好（诊断、排课、检验、进度、成果归档），专业深度内容聘请更专业的 skill"老师"来教或一起查证，绝不硬编。**

## 1. 这个 Skill 能为你做什么？

### 三个承诺

| 承诺 | 具体表现 |
|------|---------|
| **任何领域都能学** | AI Agent、Python、Git、Markdown……任何主题都适用。每个主题独立存档，可以同时学多个领域，互不干扰 |
| **当你的学习管家** | 先诊断你的基础再开讲；教学顺序科学（动机 → 类比 → 直觉 → 定义）；绝不说"你错了"；每单元拆小、强制动手、主动回忆测试；**打字负担最小化**（诊断选项化、检验判断题优先、每题一句话） |
| **输出一本学习手册** | 每个主题自动沉淀**一本《学习手册.md》**（章节=单元，含自测题/避坑/速查/术语，越学越厚），另有 `index.md` 总览和 `state.json` 进度，纯 Markdown，可复习、可迁移、可交给任何 AI 接着教 |

### 三个要知道的事实（避免误会）

1. **它不是全科教授，是管家**：基础概念它讲得清清楚楚；**超出它能力的专业深度内容，它会诚实说"这个部分有更专业的老师"并建议聘请（需你确认）或一起查证，绝不硬编**。想请专业老师时，它负责记笔记、考你、管进度。
2. **它不会替你学**：它强制你动手、复述、测试——这正是它好的地方。如果你只想"听"不想"做"，它会卡住你（主动回忆没过关就标记 `needs_review`，不让你推进）。
3. **成果按"单元"记，不是按"句话"记**：一个单元完整学完才写入《学习手册》。学一半中断（比如"我累了今天先到这"），它只保存进度和已讲部分，**不会假装把没讲的内容补完整**——下次续接时从剩下一半接着教，教完、测过，才补全手册。宁可欠着，也不让你糊弄过去。

## 2. 怎么用它（最重要的使用规则）

### 2.1 安装后你拿到的是什么

安装本 Skill 时，你拿到的是一个**独立的 Skill 文件夹**：

```
learn-like-a-pro/
├── SKILL.md                          ← 【核心】管家指令（AI 靠它知道怎么带你学）
├── README.md                         ← 本文件（面向使用者）
├── evals/
│   ├── evals.json                    ← 17 个测试场景（验证 Skill 质量）
│   └── files/ai-agent/               ← 测试用的模拟学习存档
└── references/
    ├── resume.md                     ← 【核心】续接精简指令（保留管家规则、省 Token）
    ├── teaching-examples.md          ← 完整示例对话（按需加载，平时不进上下文）
    ├── skill-collab.md               ← 专业教师协作细节（按需加载）
    └── templates/                    ← 产物模板（学习手册 / 进度 / 教师口碑）
```

**`my_learning/`（你的学习成果目录）不包含在安装包里**——它会在你**第一次使用 Skill 学习时自动生成**。也就是说：

- 刚安装 = 只有管家（老师），还没有成果
- 第一次学习后 = 项目里出现 `my_learning/<主题>/`，成果开始积累

### 2.2 一句话版（记不住细节？记住这张）

| 你想干嘛 | 打开/拷贝什么 |
|---------|--------------|
| 用这个 Skill 学新东西 | 打开**项目根目录**作为工作区（不是 Skill 文件夹！） |
| 换一个 AI 只看学习成果 | 只拷贝 `my_learning/<主题>/` 过去就行 |
| 换一个 AI 继续学某个主题 | 拷贝 **Skill 文件夹 + `my_learning/<主题>/`**，并保持相对结构 |

### 2.3 场景一：用这个 Skill 学习 → 打开项目根目录

假设你把 Skill 装到了某个项目里，结构是这样的：

```
你的项目根目录/                      ← 打开这个作为工作区 ✅
├── .agents/skills/learn-like-a-pro/   ← 管家（Skill 本体）
├── my_learning/                       ← 你的成果（学习存档，首次学习后生成）
└── （其他项目文件）
```

**为什么不能只打开 Skill 文件夹？**

AI 找学习存档的路径是 `my_learning/<主题>/state.json`——这个路径是**相对于项目根**写的。如果只把 Skill 文件夹作为工作区：

- ✅ AI 能看到 Skill（能带学）
- ❌ AI 看不到 `my_learning/`（它在 Skill 文件夹**外面**）
- 结果：每次新对话都找不到存档 → **续接失效，被迫重新诊断**

> **规则：工作区 = 项目根（Skill 和 my_learning 的共同父目录）。** 这样 AI 既找到管家，又找到你的成果。

### 2.4 场景二：换 AI 只看学习成果 → 只拷贝主题文件夹

```
拷贝：my_learning/python/        ← 够了 ✅
```

因为《学习手册.md》、`index.md` 都是**纯 Markdown**，任何 AI 打开就能读懂。**不需要 Skill**——你只是想复习，不是想继续学。

### 2.5 场景三：换 AI 继续学某个主题 → 两个一起拷贝

```
新项目/
├── .agents/skills/learn-like-a-pro/   ← 管家（Skill）必带
└── my_learning/python/                ← 成果（存档）必带
```

**只拷贝主题文件夹不够**，因为：
1. 没有 Skill，新 AI 不知道该用哪种方式带你学（不知道诊断选项、判断题检验、手册生成这些规则）
2. 即使有 Skill，如果目录结构不对（主题文件夹没放在 `my_learning/` 下），Skill 按 `my_learning/<主题>/state.json` 的路径找不到存档，照样重新开始

> **规则：换 AI 续学 = "管家"和"成果"必须保持原相对位置一起搬。**

### 2.6 完整目录总览（首次学习后的样子）

```
learn-like-a-pro/
├── SKILL.md                          ← 【核心】管家指令
├── README.md                         ← 本文件（面向使用者）
├── evals/
│   ├── evals.json                    ← 17 个测试场景
│   └── files/ai-agent/               ← 测试用的模拟学习存档
└── references/
    ├── resume.md                     ← 续接精简指令
    ├── teaching-examples.md          ← 示例对话（按需加载）
    ├── skill-collab.md               ← 专业教师协作细节（按需加载）
    └── templates/                    ← 产物模板（3 个）

my_learning/                          ← 运行时自动生成（首次学习后出现）
├── index.md                          ← 【总览】所有主题的进度仪表盘（v1.5 新增）
├── teachers.md                       ← 【教师口碑】聘请过的专业老师记录（v1.5 新增）
├── <主题1>/                          ← 目录名英文 kebab-case，如 ai-agent/
│   ├── 学习手册.md                   ← 【人读】该主题全部成果：路线图+章节+附录（越学越厚）
│   └── state.json                    ← 【机器】进度存档（AI 读，你不用打开）
└── <主题2>/                          ← 如 python/
```

## 3. 学习成果说明

一个主题学完后，`my_learning/<主题>/` 下只有 **2 个文件**，跨主题另有 **2 个总览文件**：

| 文件 | 一句话 | 什么时候看 |
|------|--------|-----------|
| `学习手册.md` | **该主题的一本书**：开头是学习路线图，正文每章=一个单元（含掌握概念/避坑/本节自测 3 题），尾部是速查卡+术语表附录和毕业检查单 | 复习、回看、考前扫一眼 |
| `state.json` | 机器读的进度存档（学到哪、哪些卡住、聘请了哪个老师） | 只有 AI 读，你不用打开 |
| `index.md`（`my_learning/` 根） | 所有主题的进度总览仪表盘 | 看全局学了多少 |
| `teachers.md`（`my_learning/` 根） | 聘请过的专业老师及其口碑 | 换 AI 时知道老师档案 |

**记忆法**：**一个主题 = 一本书（学习手册）+ 一个进度档（state.json）**。v1.5 起不再生成 5 个分散文件（notes/cheatsheet/quiz/next-steps/glossary），它们全部被吸收进《学习手册》——自测题在每章末尾就地出现，速查卡和术语表是手册附录，路线图是手册开头。

### 手册内部结构

```
# [主题] 学习手册
## 📍 学习路线图          ← 当前进度/下一步/待重学（每次覆盖）
## 第 1 章 [单元名] — [日期]   ← 每单元一章，追加（含：掌握概念/避坑/本节自测 3 题）
## 第 2 章 ...（越学越厚）
## 附录 A：速查卡          ← 滚动追加
## 附录 B：术语表          ← 滚动追加
## 🎓 毕业检查单
```

**追加策略**：章节和附录**追加**（历史永远保留）；路线图、`state.json`、`index.md` **覆盖**（状态必须最新）。

## 4. 核心设计

### 4.1 轻量化续接（省 Token，不降质量）

- **首次学习**：加载完整 `SKILL.md`（约 640 行，示例对话已拆到 `teaching-examples.md` 按需加载）→ 诊断 → 建状态文件
- **续接学习**：只加载 `references/resume.md`（约 200 行）+ `state.json`（约 30 行）
  - `resume.md` 保留核心管家规则（选项化诊断、判断题检验、支架练习、手册化产物）
  - `state.json` 提供实时进度
- 续接 Token 消耗约为完整版的 **1/3**，教学质量不降低

**上下文吃紧怎么办**：如果对话变长、感觉 AI"记性变差"（小上下文模型尤其明显），最有效的动作是**结束当前对话，用"继续学 XXX"续接**——续接会自动走 `resume.md`（Token 省约 60%+），而不是去删减 `SKILL.md`。

**缓存友好建议**：同一个主题尽量**在同一会话内连续学**（间隔超过几分钟缓存会失效）；避免频繁新建会话导致每次重载完整 SKILL.md。

### 4.2 产物按"单元"更新，不按"句话"更新

不是每轮对话都写手册，而是**每个学习单元完成后**更新一次：正文追加新章节、附录追加新条目、路线图覆盖为最新。历史记录永远保留。

### 4.3 多轮对话怎么续上的（state.json 示例）

```json
{
  "topic": "AI Agent",
  "topic_slug": "ai-agent",
  "current_unit_index": 2,
  "units": [
    {"name": "AI Agent 是什么", "status": "completed", "mastered": true},
    {"name": "Agent 是怎么思考的", "status": "needs_review", "mastered": false},
    {"name": "Skill 是什么", "status": "in_progress", "mastered": false}
  ],
  "diagnosis": {"current_knowledge": "完全零基础", "goal": "做一个简单 Agent"},
  "teacher": null
}
```

**`needs_review` 是什么意思**：当某单元卡住超过 3 次或测试 0 题对时，标记为"需重学"，**进度不推进**——续接时 AI 会优先带你重学这个单元，而不是跳过它。这保证"学完"和"掌握"是两回事：流程走完 ≠ 真懂了。

**续接流程**：
1. 用户说"继续学 AI Agent"
2. AI 加载 `resume.md` + `state.json`
3. 发现 `needs_review` 单元 → 优先重学；否则从 `current_unit_index` 继续
4. 确认"上次学到 X，今天继续吗？" → 用户确认 → 直接接着教，**不再重新问诊断**

### 4.4 多个主题并行学，互不干扰

- 每个主题独立目录：`my_learning/ai-agent/`、`my_learning/python/`
- 目录名统一**英文 kebab-case**（`ai-agent`、`git-basics`），中文名存在 `state.json` 的 `topic` 字段
- 切换主题 = 读对应目录的存档，无缝切换；`index.md` 汇总所有主题进度

### 4.5 环境没有文件权限时怎么办（fallback）

如果 AI 运行在无法写文件的对话环境（如网页版），成果不会丢——AI 会把手册章节完整内容输出在对话里，并告诉你手动保存到 `my_learning/<主题>/学习手册.md`，同时更新 `index.md`。**成果生成是核心承诺，任何环境都不跳过。**

### 4.6 提问效率（v1.5 核心改进，打字负担最小化）

- **诊断选项化**：诊断问题默认给 A/B/C/D 选项 + "其他"，点选即可，不用打长段文字
- **检验判断题优先**：AI 先自评"我认为你已经理解了，对吗？"，你只需回"对"或一句话纠偏
- **每单元保留 1 个产出型问题**（限一句话回答）——守住苏格拉底"自己说"的核心，但不让你写段落
- **主动回忆精简为 2 题**（核心思想一句话 + 应用场景一句话）

### 4.7 实践型主题适配（做游戏 / 写网站 / 写脚本）

学"做一个能跑的东西"（比如一款贪吃蛇小游戏）时，诊断会自动加深：在基础 5 问之后追加 4 问（同样选项化）——**上手程度**（写过代码吗）、**设备与环境**（装了什么工具）、**产物想象**（做出来长什么样、在哪玩）、**类型偏好**（想做什么，给你 2-3 个选项）。

- 每条追问都在为"怎么拆地图、用什么工具、产物长什么样"提供依据，不是拖延
- 关键的一问是**工具选型**：小白什么也没装 → 优先零安装方案（如网页版 p5.js），而不是上来让 TA 装 VS Code + Python 配环境
- 学习地图会把**环境搭建**作为第 1 个单元（地基），地图终点是"做出一个能玩的产物"
- 每单元按「讲 → 验 → 练 → 测」四拍走完，每拍至少 1 次提问互动

### 4.8 专业教师聘请（v1.5 起为管家核心能力）

当你想学的领域本 skill 讲得不够专业、而生态里有更专业的教学 skill 时，管家会在**学习地图规划阶段**主动识别并建议（**是否聘请由你决定**，绝不擅自安装、绝不反复推销）：

- 管家会帮你**查口碑（`teachers.md`）、找候选、评估、安装**（有 find-skills 就用，没有就引导装，装不了就诚实降级到"发资料/一起查证"）
- 装好后**分工协同**：专业 skill 讲知识（外聘老师），本 skill 管检验、练习、产物、进度（班主任）——同一时刻只有一个主导者
- **宪法条款**：即使专业 skill 直接给答案，本 skill 也会用自己的话转译成"类比先行"再考你——不因"专业老师讲了"就跳过检验
- 每次协作后把老师表现记入 `teachers.md`（口碑），下次同类主题直接复用结论
- 学习成果始终留在 `my_learning/`，换哪个老师教都不丢；不想用了随时回到纯管家模式

## 5. 工作原理（六步循环）

```
[激活]
  ↓
[检测 my_learning/<主题>/state.json]
  ├─ 存在 → 加载 resume.md + state.json → 确认续接 → 直接跳到第 ③ 步
  └─ 不存在 → 走完整流程
    ↓
① 诊断起点（选项化 5 问；实践型主题追加 6-9 问）→ 创建 state.json
  ↓
② 构建学习地图（拆成 5-10 个最小可学单元；识别可能有专业老师的单元）
  ↓
③ 知识构建（Motivation → Analogy → Intuition → Definition）
  ↓
④ 动手实践（光听不练 = 白学）
  ↓
⑤ 主动回忆测试（2 题，检测真懂还是假懂）
  ↓
⑥ 成果生成（《学习手册》追加章节 + 更新 index.md / state.json）
  ↓
[循环到下一个单元，或收尾]
```

## 6. 对话质量验证（测评结果）

> 本 Skill 用 **skill-creator 方法论** 做了完整的量化测评：让"装了本 Skill 的 AI"和"没装的普通 AI"分别回答真实学习场景，由独立评分代理按客观断言打分，对比差距。
>
> **v1.5 说明**：以下 14 场景 75 条断言是 **v1.4 实测数据**（2026-08-11）；v1.5 新增 eval 15-17（管家定位 / 提问效率 / 手册化产物，共 18 条断言，总计 17 场景 93 断言）**已写入 evals.json 但尚未在线复跑**——待在有 claude CLI + API 的环境执行。

### 测评结果（v1.4 实测：14 个场景，75 条断言）

| 指标 | 装 Skill 的 AI | 普通 AI（无 Skill） | 差距 |
|------|---------------|-------------------|------|
| 综合通过率（12 个经典场景） | **100%** | **74.4%** | **+25.6%** |
| 实践型主题诊断（eval 13 新增） | **8/8** | **6/8** | 普通 AI 让小白直接装 VS Code，无零安装方案 |
| 专业 skill 协作（eval 14 新增） | **7/7** | **3/7** | 普通 AI 不提供选项/候选/安装确认，给答案后不检验 |

### 十四个场景覆盖了什么

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 零基础学 AI Agent | 诊断纪律：只问第 1 问、不直接讲概念、语气鼓励 |
| 2 | 动手写第一个 Skill | 教学前诊断、给出具体格式指令、引导而非代做 |
| 3 | 迷茫不知道学什么 | 情绪支持、兴趣发现、不过早推荐 |
| 4 | 续接学习（"继续学 AI Agent"） | 检测存档、跳过重复诊断、`needs_review` 优先重学 |
| 5 | 无文件系统环境 | 承诺 fallback、告知保存路径、教学不中断 |
| 6 | 多轮完整教学对话（Markdown） | 完整教学链：诊断→地图→类比先行→苏格拉底检验→主动回忆 |
| 7 | 多轮对话·换技术主题（Python） | 验证教学纪律与主题无关 |
| 8 | 多轮对话·非技术主题（历史） | 验证非技术主题适配，实践因地制宜 |
| 9 | 内容正确性（Git commit） | 验证 AI 教的概念与官方语义一致 |
| 10 | **长对话·15 轮耐力测试（Python）** | **验证规则是否随对话变长而漂移** |
| 11 | **资料驱动学习（用户发 Git 资料）** | **读取资料→基于资料教学→指出资料缺口** |
| 12 | **资料读不了的环境** | **诚实告知、粘贴 fallback、不编造** |
| 13 | **实践型主题诊断（做贪吃蛇游戏）** | **追加 6-9 问、零安装方案选型、环境搭建为第 1 单元** |
| 14 | **专业 skill 协作** | **显式触发不推销、能力检测、2-3 候选评估、安装确认、宪法条款** |
| 15 | **管家定位+专业教师聘请（v1.5 新增）** | **地图规划阶段主动建议聘请、不硬编、查口碑、教师给答案仍检验** |
| 16 | **提问效率（v1.5 新增）** | **诊断选项化、判断题优先、一句话回答、不要求打大段文字** |
| 17 | **手册化产物（v1.5 新增）** | **产物为《学习手册》+ index.md，不再列 5 个旧独立文件** |

### 关键发现（差距在哪里，v1.4 实测）

- **最核心的差距——"类比先于定义"**：完整教学对话中，普通 AI 教"轻量级标记语言"时是**定义先行、例子殿后**；装了本 Skill 的 AI 会先给"菜单上画记号"的生活类比，再给正式定义。
- **诊断纪律**：普通 AI 会零诊断直接倒知识给小白；本 Skill 强制先问诊断，绝不跳过。
- **绝不信"懂了"**：用户说"感觉掌握了"时，普通 AI 直接继续；本 Skill 会用检验问题确认真懂。
- **长对话规则漂移**：对话越长，普通 AI 越容易"忘规矩"——15 轮后半段它直接放行"感觉掌握了"；装本 Skill 的 AI 到第 14 轮仍守纪律。

### 测评怎么做的（简版）

1. 每个场景跑 2 个 AI：一个装本 Skill，一个不装（对照组）
2. 由独立评分代理按**可客观验证的断言**打分
3. 聚合所有场景的通过率，对比差距

> 测评数据与完整报告在 `learn-like-a-pro-workspace/` 目录（如有附带）。

### 使用者该怎么看这些数字（诚实解读）

1. **+25.6% 是"教学纪律"的提升，不是"知识水平"的提升**——它保证 AI 每次都按科学方法教你（先诊断、先类比、不批评、检验真懂），而不是偶尔做得好。对学习者来说，**一致性比峰值更重要**。
2. **普通 AI 本身也有 74%**——现代 AI 自带不错的教学能力。本 Skill 的价值是把"好的教学"从"偶尔发生"变成"每次发生"。
3. **100% 有"同源"水分**——测试断言是按本 Skill 的设计写的，天然偏向装了 Skill 的 AI。真实教学效果还需你亲自体验判断。
4. **未验证的盲区**：① 技能型非技术主题（弹钢琴、游泳这类"练"多于"学"的内容）；② 冷门领域的知识正确性（取决于模型知识，Skill 只能引导查证、不能保证正确）；③ 长期多单元教学；④ v1.5 新增的 3 个 eval（15-17）尚未在线复跑。

#### 结论

本 Skill 是一套**经过量化验证的教学行为规范**：它能可靠地让 AI 按科学教学法陪你学习、把关键教学要素讲全、在超纲时引导查证或聘请专业老师而非编造、并自动沉淀为一本可复习的学习手册；它**不承诺**提升 AI 的知识正确性。**用一句话说：它保证"教得对路、管得周全、不懂会查"，不保证"教得都对"——最后一点取决于你聘请的老师（专业 skill）和你使用的 AI 模型。**

## 7. 安装

### 方法 1：直接放入项目

```bash
# 将本目录复制到你的项目 .agents/skills/ 下
cp -r learn-like-a-pro /your-project/.agents/skills/
```

### 方法 2：使用 skills CLI

```bash
npx skills add /path/to/learn-like-a-pro -y
```

> 装好后，如果你之前学习过（已有 `my_learning/`），记得把它一起迁移到新项目——否则新环境会重新开始。
